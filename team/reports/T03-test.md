## Changes to tests (what was wrong and what I did)

1. `tests/content.test.mjs`, "index.json has a numeric version": expected version 6 (the old baseline). Changed to 7, as D3 requires.
2. `tests/content.test.mjs`, "word count per item (baseline, expected to change in upgrade-1)": it pinned an exact phrase table and tallies from the old one-word and two-word content. It would have failed against the new, correct content. Removed and replaced by rule tests (3-4 words, at least 10 with 4 words, no `. ! ? ,`, lower-case except "I", one emoji per item within the Unicode limit, wordsPerVisit 10, ids s1..s25 in order). The rule tests check the rules, not a phrase list, so they do not need updating on every wording change.
3. The old baseline test "no phrase has ... sentence punctuation" was left unchanged. It still passes and the new comma rule is in the new rules test.

## Emoji check: limits

The emoji test uses the simple allow check agreed in the task, not a full Unicode version table. It checks: one code point after removing U+FE0F, code point <= U+1FAFF, not in U+1F971-U+1F97F, and not >= U+1FA70. Some Unicode 12+ emoji below U+1FA70 (for example in U+1F90x to U+1F97x ranges outside the rejected block) would not be caught. The 25 emoji were checked against my knowledge of the emoji lists (for example the butterfly U+1F98B is Unicode 11 and the teddy bear U+1F9F8 is Unicode 10). I did not check them against a Unicode data file. The Coder's note says all are Unicode 9 or older; I did not verify that separately.
